# AI 助手部署协议

## 1. 用途

本文件规定 AI 助手协助部署 TeamHub 时的权限边界和交接点，不是一段绑定特定 tag 的一次性提示词。

## 2. 默认授权范围

在用户指定的部署目录内，助手可以：

- 检查 Node、git、端口和仓库状态。
- 获取用户明确指定的版本，安装依赖，构建并绑定 loopback 启动。
- 读取 `/health`、系统状态和普通日志中的非秘密错误。
- 运行仓库已有的备份、验证和非破坏性诊断命令。

未得到额外授权时，助手必须停在“loopback 上服务可访问、等待用户初始化”的状态。

## 3. 禁止自动执行

- sudo、systemd、SSH 到其他主机、修改防火墙/反代、开放 80/443。
- 读取或打印 `.env`、App Secret、WRITE_TOKEN、PIN/hash 或 provider key。
- 导入真实名册、代用户选择产品模式、初始化管理员或设置 PIN。
- 删除卷、覆盖数据、执行破坏性迁移、删除 tag 或发布 Release。
- 遇错反复重试；同一方向最多自行修复两次，然后按 archive 协议查历史并报告。

## 4. 标准执行序列

1. 记录目标目录、目标 commit/tag 和当前运行实例。
2. 检查前置条件；缺系统级依赖时停止并报告。
3. 获取代码和依赖，在 loopback 启动。
4. 报告 `/health`、buildId、VERSION 和 setup 状态。
5. 用户通过本地浏览器/安全隧道完成产品选择、名册和管理员初始化。
6. 用户明确授权后，助手才可按部署方案开放内网或配置守护进程。
7. 变更真实运行状态前备份；完成后回报备份位置、运行 commit 和恢复方法。

## 5. 异常处理

- 构建、启动或数据行为与活文档矛盾：停止扩展修改，查 `docs/archive/README.md` 对应事故或决策。
- 数据、权限、事务、配置、存储和飞书问题必须在结论中注明命中的 archive ID。
- 不能证明目标路径和数据副本安全时，不执行删除、移动或覆盖。
- 报错必须保留 exit code 和关键上下文，但先移除秘密值。

## 6. 交接报告

助手最终至少报告：

- 实际运行的 commit SHA、VERSION、buildId、监听地址和启动形态。
- 使用的数据库后端和数据/artifact 落点（不含秘密）。
- 运行过的备份和检查及其结果。
- 尚需用户完成的初始化、开放网络或外部平台审批。
- 明确的停止/回滚命令，但不在未授权时替用户执行。
