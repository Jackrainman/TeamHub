## 1. 修正 D-042 基调③：对话记账判死（作为主力路径）

- **判死理由（用户口径）**：真实队员不会主动对 AI 说"今天坏了两个滑轨"——期待日常对话喂账本是幻想，账本会静默饿死。
- **保留**：`PartAction.source='hermes'` 枚举与 append-only 动作日志不动（未来出站通知/生成器用途仍在）；`note` 一句话快记仍是 console 录入的低摩擦形态。
- **防死机制改向**：记账必须是**必要动作的副产品**——盘点建底（已有）、装箱门核对（§5）、两箱法物理触发（§2）。凡指望"人闲下来主动录入"的路径一律不再作为设计依赖。
- **AI 的新位置**：从"录入界面"降级为"清单生成器"（§5 装箱预填）。AI 生成、人勾选确认，写入仍走结构化动作。

## 2. 记账粒度分级（三档，拒绝一刀切）

| 档 | 例子 | 记法 | 系统改动 |
|---|---|---|---|
| 耗材 | 螺丝/扎带/热缩管/焊锡 | **不进系统**。两箱法：每种备两盒，开第二盒的物理动作=采购触发（拍照丢群/盒上贴卡） | 零。系统不强求全覆盖——记不上的账不如不记 |
| 数量件 | 打印耗材/常用模块/轴承 | `PartType` 现有模型（totalQuantity + lowStockThreshold）够用 | 零 |
| 贵重件 | 电机/电调/主控 | `TrackedPart` 个体行 | 见下 |

- **贵重件个体行两处增强**（实现期落）：
  1. `TrackedPart` 加 `note: string | null` 自由备注——"缺减速箱""没输出轴""编码器异响"全写这里。**不建子类型**："缺减速箱的 3508"不是新类型，是个体状态；用备注列吃掉全部长尾，拒绝 OOP 化建模。
  2. **status 语义收口：机器只算 ok 数**——一切派生量（可用数/水位报警/BOM 余量）只统计 `status='ok'` 的个体；`damaged`/`retired` + note 给人看、不给机器算。

## 3. 缺料双报警 = 两条派生查询（非常驻进程、非新实体）

1. **备件水位**（既有 `lowStockThreshold` 的收口）：闲置且 ok 的数量 < 安全线 → 告警。覆盖一切**曾经有过**的物料；**水位可以为 0**（"这种件我们不备"也是显式决策，设 0 即不再骚扰）。
2. **采购缺口**（新增语义）：BOM/需求清单中**从未有过**对应 PartType（或历史 totalQuantity 恒 0）的项 → "该买而从没买过"。数据前提=BOM 侧存在需求行；无 BOM 数据时此报警自然为空集，**不硬造需求源**。

两条都是读侧纯函数（照 deriveBaselineDrift 先例），进总览页告警区即可，不建后台任务。

## 4. 赛场打标：一本账 + 打标，不是两本账

- 位置维度候选形态（实现期定，本文只锁原则）：`TrackedPart` 加 `site: 'lab' | 'venue'`（默认 lab）；数量件加 `venueQuantity`（≤ totalQuantity 的子集计数）。
- "带到赛场"视图 = 主账按打标**过滤**，绝不复制出第二本账（双写即腐烂）。
- 水位报警可按 site 分算（赛场安全线单设或复用 lab 值）——实现期定。

## 5. 装箱门：出征 = 一次转移单核对（hybrid 形态）

- 装箱 = 批量打标动作（lab→venue），落 `PartAction`（新 kind `'transfer'` 或扩展 fromHolder/toHolder 语义——实现期定）。
- **hybrid**：agent 从 BOM × 上届装箱清单生成**预填检查表**，人逐项勾选确认 → 批量落 transfer 动作。agent 只当清单生成器、不当录入界面（守 §1）。
- 回程逆向核对同一张表：**丢失当场显形**，而不是下赛季找件时才发现。

## 6. 红线不动

I0（recordedBy 永无 memberId、无按人聚合）/ G2（不回写飞书 Bitable）/ C3（拆装只移 currentHolder、绝不删 TrackedPart 保血缘）/ append-only PartAction 仍是唯一动作日志。本文全部改动均为读侧派生 + 少量 optional 字段，无破坏性迁移。
