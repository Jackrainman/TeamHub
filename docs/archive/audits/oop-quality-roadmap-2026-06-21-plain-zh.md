## 一、这次干了啥

给整个项目做了一次全面"体检"：派了一大批 AI 分头从八个角度翻代码找毛病，再让另一批 AI 互相挑刺、逐条核对，确认每条毛病是真的、不是冤枉的。

最后把毛病分成两类：**52 条线索 → 21 条"真该处理" + 31 条"看着怪但其实是故意的，别动"**。

---

## 二、总体结论：整体很健康

项目"骨架"搭得不错。特别要说明一点：有些地方**乍看不像常规写法，AI 一开始也想按常规去改，但对照当初的设计文档后发现——是故意这么设计的，不能动，动了反而坏事**。比如：

- **不给队员排名、不显示"谁快谁慢"**——刻意防止这工具变成"监视谁摸鱼"；
- **同一份数据只存一处、不重复记账**——避免两边对不上；
- **一些当初就讨论决定"先不搞"的复杂功能**——小作坊够用就行，不铺张。

这类"看着怪、其实对"的，加上**一批早就已经修好的旧毛病**，一共 31 条，全都留着没碰（清单见第五节）。

## 三、真该处理的 21 条（都是"小毛病/隐患"，不是正在出错的故障）

分成三摞，按"越省事越靠前"排。

### 第一摞 · 顺手就能清（最省事，风险最低）

| 编号 | 大白话说明 |
|---|---|
| **A1** | 删掉一个"撤销用"的废功能——它压根没人用，它声称要应付的场景在代码里根本不存在。 |
| **A2** | 删掉一行既没用、还会误导后人的代码。 |
| **A3** | 删掉几处"过时的类型逃生口"——它们当年是临时绕路，现在反而让"拼写写错了能自动发现"这个保护失灵。 |
| **A4** | 有一段"报错信息怎么显示"的写法被复制了 **17 遍**，收成一个共用的小函数，以后想改一处就够。 |
| **A5** | ⚠️ **这是唯一一个真 bug**：排班的"接力交接"那块，目前允许连出一根"断头线"——指向一个不在当天的班次，画面上会出现没头没尾的箭头。修掉它，并补一个自动检查防止复发。 |
| **A6** | 排班那块有一段"组装数据"的代码被抄了两遍，收成一处；顺手让它跑得更快一点点。 |
| **A7** | 有三个"读取清单"的功能，返回的是"原件"而不是"复印件"——理论上外人能绕过规矩直接改原件。改成返回复印件，跟项目里其他读取功能保持一致。 |
| **A8** | 前端和后端各自把网址（接口地址）硬写了一遍，将来一边改名、另一边会悄悄对不上。可以统一管理。**但价值不高、不着急**，要做就一次全做、别做一半。 |

### 第二摞 · 防患于未然（稍微动到"地基"，但价值高）

| 编号 | 大白话说明 |
|---|---|
| **B1** | 有一份**关键数据结构**，现在"在三个地方各抄了一份、全靠人记得同步"。眼下三份对得上、没出事；但哪天给它加东西时漏改一处，重启时会**悄悄丢数据还不报错**。第一步：给"加载数据"那道关加一道保险（不会再静默丢字段）+ 一个"对不上就报警"的哨兵。 |
| **B2** | 接着上一条——把那份"三处各抄一份"里的清单收拢成"**一份真相**"，以后只需维护一处。建议和 B1 一起做（改的是同一个文件）。 |
| **B3** | 有一个编号，规矩是"**禁止手填、必须系统自动生成**"。现在虽然网页表单那层挡住了手填，但底层还留着一个能手填的口子。把这口子彻底封死，让它像别的自动字段一样想填都填不进去。 |

### 第三摞 · 补"自动考试"（纯加检查，碰不到正在跑的功能，零风险）

意思是：给一些"从来没人验过"的功能补上自动测试，将来谁不小心改坏了，能立刻被发现。

| 编号 | 大白话说明 |
|---|---|
| **C1** | ⚠️ **最该先做**：远程登录用的"密码门"现在**完全没测过**。这道门是将来把系统放到网上时、防止外人乱写数据的唯一关卡。万一它哪天坏了（比如把正确密码也挡在门外，或干脆放行），没有任何自动检查会发现。上网前必须先补这个。 |
| **C2** | "昨天/今天/明天"这套日期计算没测过，尤其是跨月、闰年这种容易算错的边界。补上。 |
| **C3** | 排班画面"按设备分泳道"的归类逻辑没测，补上。 |
| **C4** | "填了名字 → 生成记录人"的逻辑没测——而且它关系到隐私（名字留空时绝不能乱记一个人头上）。补上，顺便把这条隐私底线钉死。 |
| **C5** | 依赖关系图的"自动排版"没测。**价值不高，可以最后做**。 |
| **C6** | 库存的"录入零件 / 记一笔（用了、坏了）"在前端这层没测，补上。 |
| **C7** | "上传图纸文件"那条路没测，补上。 |
| **C8** | 几个到处都在用的通用小工具（比如"把一串逗号隔开的文字拆成清单"）没测，补上。 |
| **C9** | 给第二摞 B1 提到的那份"易丢字段"的数据，加一个"少一个字段就考试不及格"的检查。**注意：和 B1 的哨兵二选一即可，别重复做。** |

## 四、建议怎么推进

1. **先补"密码门"测试（C1）**——上网前的硬要求。
2. **再清第一摞（A1~A7）**——省事、低风险，里头那个真 bug（A5）顺手修了。
3. **最后做第二摞（B1+B2 一起、B3 单独）**——收拢数据、堵漏洞。
4. **第三摞其余的补测（C2~C8）** 随时可以插空做，碰不到正在跑的功能。

**有几条提醒**：

- 凡是动到"后端正在跑的功能"的改动，按项目规矩要顺手升一下版本号（有现成脚本，别手改）。
- 纯加测试（第三摞大部分）不用升版本号。
- **全部 21 条都做过"红线检查"，没有一条会破坏前面说的那些底线**（不排名、不暴露谁快谁慢、隐私、数据只存一处）。其中 B3 反而让"自动生成编号"的规矩更牢，C1/C4 的测试反而把隐私底线钉得更死。
